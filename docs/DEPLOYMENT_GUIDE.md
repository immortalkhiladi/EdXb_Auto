# EDGAR Agents LLC Portal — Deployment Guide

Written for a developer who has used VS Code but may be new to GitHub and cloud hosting. Every command below is
taken from this repository's real configuration. Values you must supply yourself are marked **`<CONFIRM>`**.

---

## 1. Architecture

```
Browser ──HTTPS──> Render web service (one origin)
                     ├─ Django 5.2 + gunicorn      /api/*   JSON API: auth, MFA, documents, admin, tool pages
                     └─ WhiteNoise                  /*      the built React app (frontend/dist)
                     └──TLS──> Render PostgreSQL     users · sessions · documents · audit log · FILE BYTES
```

* **Frontend:** React 19 + Vite 8 + Tailwind CSS 4 (`frontend/`). Built once; Django serves the static output.
* **Backend:** Django 5.2 (`backend/`), gunicorn, PostgreSQL (psycopg2). SQLite is allowed locally only.
* **Tools:** four self-contained HTML tools in `backend/tools/`. They run **entirely in the browser** inside a
  sandboxed iframe (opaque origin, no cookies). Nothing is executed on the server: no LibreOffice, no InDesign, no
  system packages. The server only authenticates the user, serves the page, validates and stores results.
* **Files:** stored inside PostgreSQL in chunks (`STORAGE_BACKEND=database`). The container's disk is disposable, so
  **no persistent disk is required**.
* **Background work:** a lightweight in-process daily purge (`RUN_PURGE_SCHEDULER=true`, default) — no worker service.

### Repository structure
```
backend/            Django project (config/, portal/, tools/, tests/, manage.py, requirements*.txt, startup.sh)
frontend/           React app (src/, index.html, vite.config.js, package.json)  → npm run build → frontend/dist/
deploy/render/      build.sh (Render build command) · pre-release-check.sh
deploy/vm/          optional scripts for a self-managed Linux VM
docs/               this guide, SECURITY.md, ARCHITECTURE.md, OPERATIONS.md, ASSESSMENT_AND_QA.md, …
render.yaml         Render Blueprint (web service + PostgreSQL)
.github/workflows/  CI: backend tests, frontend tests + production build
run.sh / run.bat    one-command local start
```

## 3. Local setup

```bash
# 1. open the folder in VS Code:  File > Open Folder > EA_Automation   (Terminal > New Terminal for the commands below)

# 2. backend
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell:  .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
cp .env.example .env               # Windows: copy .env.example .env   → edit DB_* or set DB_ENGINE=sqlite
python manage.py migrate
python manage.py seed_users        # dev admin: admin / Admin@123 (SEED_USER_COUNT=10 adds md01 + user01..user10)
python manage.py runserver 127.0.0.1:8000

# 3. frontend (second terminal)
cd frontend
npm ci
npm run dev                        # http://127.0.0.1:3000 — Vite proxies /api to Django
```
Or simply run `./run.sh` (macOS/Linux) / `run.bat` (Windows), which does all of the above and serves the built UI from
Django at http://127.0.0.1:8000.

### Environment variables (`backend/.env`, never committed)
| Variable | Local | Production (Render env vars) |
| --- | --- | --- |
| `DJANGO_SETTINGS_MODULE` | `config.settings.local` | `config.settings.production` |
| `DB_ENGINE` | `postgres` or `sqlite` | `postgres` |
| `DB_NAME` `DB_USER` `DB_PASSWORD` `DB_HOST` `DB_PORT` | your local DB | wired from the Render database by `render.yaml` |
| `DB_SSLMODE` | – | `require` |
| `DJANGO_SECRET_KEY` | optional (auto-generated) | **required**, 50+ chars, generated by Render, **never change it** (encrypts MFA secrets) |
| `DJANGO_ALLOWED_HOSTS` | localhost | **required**: your domain(s), comma separated (`*.onrender.com` host is added automatically) |
| `ADMIN_MFA_REQUIRED` | `false` | **must be `true`** |
| `STORAGE_BACKEND` | `database` | `database` |
| `FRONTEND_URL` | `http://localhost:3000` | `https://<your domain>` (used in password-reset emails) |
| `EMAIL_HOST` `EMAIL_PORT` `EMAIL_HOST_USER` `EMAIL_HOST_PASSWORD` `EMAIL_USE_TLS` `DEFAULT_FROM_EMAIL` | optional (emails print to console) | **required for "Forgot password"** — `<CONFIRM>` your SMTP provider |
| `CSRF_TRUSTED_ORIGINS` `CORS_ALLOWED_ORIGINS` `FRAME_ANCESTORS` | localhost | only for split hosting (UI on another origin) — not needed in the default single-origin layout |
| `MAX_UPLOAD_MB` `SESSION_IDLE_MINUTES` `DELETED_FILE_RETENTION_DAYS` | 50 / 30 / 30 | same |
| `WEB_CONCURRENCY` `GUNICORN_THREADS` | – | 2 / 4 (defaults in `backend/startup.sh`) |

Split hosting only: `frontend/.env.production` with `VITE_API_BASE_URL=https://api.<domain>/api` (public, baked into JS).

## 4. The tools

| Slug (API) | UI route | File | Inputs it reads | Output it saves |
| --- | --- | --- | --- | --- |
| `redline-to-gofiler-html` | `/redline-gofiler` | `Redline_to_GoFiler_HTML_v2.html` | `.htm .html .docx` | updated HTML / review reports |
| `html-converter` | `/html-converter` | `GoFiler HTML Converter.html` | `.htm .html .docx` | GoFiler HTML (+ report) |
| `ppt-pdf-converter` | `/converter` | `PDF converter.html` | `.pdf .pptx .ppt` | EDGAR HTML package (`.zip`) |
| `sec-form-dashboard` | `/sec-forms` | `SEC_Form_Type_Dashboard.html` | `.htm .html .txt .xml .zip` (validator) | none — reference / checks only |

Each tool: `GET /api/tools/<slug>/frame` (session required) returns the page with an injected bridge script and a
sandbox CSP; when a tool triggers a download, the parent page uploads it to `POST /api/process/<slug>`, which
validates by content, stores it and lists it under *My Documents*. External dependencies are loaded from
`cdnjs.cloudflare.com` and Google Fonts only (already allowed by the CSP in `backend/portal/views/tools.py`).
Admins assign tools per user under **Admin Console → Tool Access**.

## 6. Publish to GitHub (from VS Code)

The folder is **not** a Git repository yet. In the VS Code terminal, inside `EA_Automation`:

```bash
git status                       # "fatal: not a git repository" confirms there is no history to protect
git init -b main
git add .
git status                       # review: backend/.env, .venv, node_modules, frontend/dist must NOT appear (.gitignore)
git commit -m "EDGAR Agents LLC portal: rebrand, SEC Form Type Dashboard tool, deployment docs"
```
On **github.com**: *New repository* → name `edgar-agents-portal` (`<CONFIRM>`), **Private**, do **not** add a README/.gitignore
(the repo already has them) → *Create*. Copy the HTTPS URL, then back in the terminal:
```bash
git remote add origin https://github.com/<org-or-user>/edgar-agents-portal.git
git push -u origin main
```
Verify on github.com that `backend/`, `frontend/`, `render.yaml`, `docs/` are present and `backend/.env` is **absent**.
Optional: `git checkout -b production` for a release branch; Render can deploy from either branch.

### Security checklist (done before publishing — nothing to rotate)
* `backend/.env` is git-ignored; the copy in the folder is identical to `.env.example` (local placeholder DB password
  `MyApp@123`, no real secrets). `backend/data/` (local credentials file, SQLite, uploads) is git-ignored.
* No API keys, tokens or certificates in the source. The repository has no Git history, so nothing was ever committed.
* `seed_users` is refused under production settings; use `create_admin` in production.
* Client documents: none are included; `backend/tools/SEC_Form_Type_Dashboard.html` contains only a fictitious
  "ABC Corp" sample filing.

## 7. Deploy to Render (recommended)

1. **Dashboard → New → Blueprint** → connect GitHub → pick the repository and branch → Render reads `render.yaml` and
   proposes: web service `edgar-agents-portal` (Python, plan *starter*, region *oregon*) + PostgreSQL `ea-db`
   (plan *basic-256mb*). Change region/plans if you wish (§10 costs).
2. Fill the `sync: false` variables when prompted (you can also set them later under *Environment*):
   `DJANGO_ALLOWED_HOSTS` = `portal.edgaragents.com` `<CONFIRM domain>` (or leave the onrender host only),
   `FRONTEND_URL` = `https://portal.edgaragents.com`, `EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`,
   `DEFAULT_FROM_EMAIL` = `EDGAR Agents LLC <no-reply@edgaragents.com>` `<CONFIRM>`.
   `DJANGO_SECRET_KEY` is generated by Render. `ADMIN_MFA_REQUIRED`, `STORAGE_BACKEND`, `DB_*` come from the blueprint.
3. **Apply.** Build = `bash deploy/render/build.sh` (pip install → `npm ci && npm run build` → pre-compress).
   Start = `bash backend/startup.sh` (`migrate` → gunicorn on `$PORT`). Health check: `/api/health`.
   Root directory: repository root (leave empty).
4. First admin (once): service **Shell** → `cd backend && python manage.py create_admin --username <name> --email <email> --name "<Full Name>"`.
   Sign in at `https://edgar-agents-portal.onrender.com` (actual name shown in the dashboard), enrol MFA, create users
   under *Admin Console*.
5. Verify the first deploy: `/api/health` → `{"status":"ok"}`; login page shows EDGAR Agents LLC branding; open each
   tool; run one file through *GoFiler HTML Converter* and confirm it appears under *My Documents*.

No CORS configuration is needed: UI and API share one origin. If you ever host the UI elsewhere, set
`CORS_ALLOWED_ORIGINS`, `CSRF_TRUSTED_ORIGINS`, `FRAME_ANCESTORS` to that origin and build the UI with `VITE_API_BASE_URL`.

### Custom domain + HTTPS
Render → service → *Settings → Custom Domains → Add* `portal.edgaragents.com` `<CONFIRM you control edgaragents.com DNS>`.
Create the DNS record Render shows (a `CNAME` to `<service>.onrender.com`; for an apex domain use the `A`/`ALIAS` value
shown). Render issues and renews the TLS certificate automatically once DNS resolves (`dig portal.edgaragents.com` /
https://dnschecker.org). Then add the domain to `DJANGO_ALLOWED_HOSTS` and set `FRONTEND_URL` → *Save* (the service
restarts). Test login, MFA and a password-reset email on the production domain.

## 8. Ongoing operation

| Task | How |
| --- | --- |
| Ship a change | commit in VS Code → `git push` → Render auto-deploys the branch (watch *Events / Logs*) |
| Logs | service → *Logs* (build + runtime, gunicorn access log); database → *Logs/Metrics* |
| Roll back | service → *Events* → previous successful deploy → *Rollback* (code only; run `python manage.py migrate portal <n>` in Shell only if a migration must be reversed) |
| Env vars | service → *Environment*; saving restarts the service. Never change `DJANGO_SECRET_KEY` |
| Dependencies | bump `backend/requirements.txt` / `frontend/package.json`, run `deploy/render/pre-release-check.sh`, push |
| Backups | Render PostgreSQL daily backups (paid plans) + `pg_dump` (see `README_POSTGRESQL.md` §6) — files live in the DB, so one backup covers everything |
| Monitoring | Render health checks on `/api/health`, email alerts under *Notifications*; failed logins: *Admin Console → Overview / Audit Log* |
| Staging | duplicate the blueprint with a `staging` branch (second web service + DB); keep production on `main` |
| Retention | deleted documents purged after `DELETED_FILE_RETENTION_DAYS`; audit rows after `AUDIT_RETENTION_DAYS` |

## 9. Hosting platform comparison

The deciding facts: a **Python/Django server process** (not static, not serverless-friendly because of sessions +
in-process scheduler), **PostgreSQL** holding the files, **no persistent disk**, **no background worker**, browser-side
tools (no OS packages).

| Platform | Fit | Notes (verified Oct 2026 on official pricing pages) |
| --- | --- | --- |
| **Render** (primary) | ✅ best fit | Blueprint already in repo; managed PostgreSQL, auto-deploy from GitHub, health checks, rollbacks, custom domains + auto TLS, logs. Web service $7/mo (0.5 CPU / 512 MB) or $25/mo (1 CPU / 2 GB); PostgreSQL $6/mo (256 MB) or $19/mo (1 GB); free tiers exist but free web services sleep and are unsuitable for production. |
| **Railway** (alternative) | ✅ good | Same shape (service + Postgres), usage-based: Hobby $5/mo incl. $5 usage, then $10/GB RAM/mo + $20/vCPU/mo. Needs a `railway.json`/Nixpacks config instead of `render.yaml` (build: `bash deploy/render/build.sh`, start: `bash backend/startup.sh`, health `/api/health`). Slightly less predictable monthly cost. |
| **Fly.io** | ⚠️ workable | Container-based (`Dockerfile` + `fly.toml` needed — none in repo), Postgres is "unmanaged" (you operate it). More control, more operations. |
| **Vercel / Netlify** | ❌ | Static + serverless; a long-running Django/gunicorn process with DB sessions and an in-process scheduler does not fit. Could host only the UI in a split layout, adding CORS/CSRF complexity for no benefit. |
| **VM / container (AWS Lightsail, DigitalOcean, Azure)** | ⚠️ | Works (`deploy/vm/` scripts exist) but you own OS patching, TLS, backups, PostgreSQL. Choose only if policy requires your own infrastructure. |

**Recommendation:** Render (primary), Railway (alternative). Both run the whole app as one service + one managed
PostgreSQL; there is no separate frontend host, worker or file store to manage.

## 11. Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| Build fails at `npm ci` | lockfile out of date → run `npm install` locally, commit `package-lock.json` |
| `ImproperlyConfigured: DJANGO_ALLOWED_HOSTS…` on start | set the variable (your domain) in *Environment* |
| `ADMIN_MFA_REQUIRED must be true` | set it to `true` (production refuses otherwise) |
| `DB_HOST must be the PostgreSQL server host name` | `DB_*` not wired — re-apply the blueprint or set them from the database page |
| `/api/health` returns 503 | database unreachable: check DB status, region, `DB_SSLMODE=require` |
| Login works but reset email never arrives | `EMAIL_*` unset/wrong; check service logs for the SMTP error |
| Tool page blank | browser blocked `cdnjs.cloudflare.com`/Google Fonts (corporate proxy), or the service CSP was edited |
| `CSRF verification failed` | the request came from a different origin → add it to `CSRF_TRUSTED_ORIGINS` |
| Locked out | wait 15 min, or admin *Unlock*; lost every admin → Shell `python manage.py create_admin …` |
